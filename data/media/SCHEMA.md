# data/media — קורפוס התבטאויות של המועמדים הריאליים

תשתית לאיסוף כל ההתבטאויות הפומביות (רשתות חברתיות + אזכורי חדשות) של
המועמדים הריאליים בכל המפלגות, לקראת מנוע חיפוש לפי נושאים: ציטוטים,
הבטחות והצלבת אמירות סותרות.

## צנרת

1. `python3 scripts/build_media_roster.py` — בונה את `roster.json`:
   מועמדים ריאליים (מקום ברשימה ≤ ממוצע המנדטים ×1.25 + 2, ומנהיגי
   מפלגות שטרם פרסמו רשימה), עם קישורי הרשתות הידועים. השלמת קישורים
   חסרים: `handles_overrides.json` (מפתח = id ברוסטר).
2. `python3 scripts/collect_media.py [ids…]` — אוסף דרך Bright Data CLI:
   פוסטים מ-X/אינסטגרם/טיקטוק/פייסבוק ואזכורים מאתרי החדשות המרכזיים.
   גולמי ב-`raw/` (לא נכנס לגיט), מנורמל ב-`corpus/<id>.jsonl`.
   הרצה חוזרת ממזגת לפי URL — אפשר להריץ שוב ושוב ולצבור היסטוריה.

## מבנה רשומת קורפוס (`corpus/<id>.jsonl`, שורה = רשומה)

```json
{
 "candidate_id": "yair_golan",
 "candidate_he": "יאיר גולן",
 "party": "democrats",
 "source_type": "social_x",     // social_x | social_instagram | social_tiktok | social_facebook | news
 "source_name": "x",            // או דומיין האתר עבור חדשות
 "date": "2026-08-27",          // חובה לפוסטים; null רק כשמקור החדשות לא מדווח תאריך
 "url": "https://x.com/...",    // חובה תמיד — קישור למקור
 "text": "הציטוט המילולי…",
 "engagement": 1234,            // לייקים אם ידוע
 "collected_at": "2026-08-29T19:20Z"
}
```

**כללי ברזל:** לכל רשומה תאריך וקישור למקור. רשומה בלי URL לא נכנסת
לקורפוס; פוסט בלי תאריך לא נכנס. הטקסט נשמר מילולית (עד 2,000 תווים)
כדי שציטוט יהיה תמיד בר-אימות ובר-שיתוף.

## מה זה נותן בהמשך

- **חיפוש לפי נושא** — אינדקס טקסטואלי על `text` (למשל embeddings או
  BM25) מעל כל הקורפוס.
- **הבטחות** — סינון התבטאויות עתידיות ("נעביר", "נבטל", "אני מתחייב").
- **סתירות** — הצגת ציטוטים של אותו מועמד על אותו נושא לאורך זמן, זה
  לצד זה, עם תאריך ומקור לכל אחד. הכלי מציג את המקורות; שיפוט אם מדובר
  ב"שקר" נשאר לקוראים — לכן החובה על תאריך + קישור בכל רשומה.

הצגה באתר: `/knesset/quotes` (עמוד הציטוטים, כולל שיתוף ציטוט כתמונה).
